# LDC 批量分发 🐒

Tampermonkey 用户脚本：名单来源自由（粘贴 id/username JSON、整份 /u/用户名.json、按用户名查询添加、快捷键 Alt+F 一键拉取我的粉丝）→ 统一/单独设置额度 → 通过你自己的 [credit.linux.do](https://credit.linux.do)（LDC）商户密钥**批量打款**。

- **无后端业务、无登录、无数据库**：名单、额度、批次审计全部存本机浏览器（GM_* 沙箱存储），可随时导出
- **除 LDC 支付接口、linux.do 同源名单接口与 linux.do/ldstatic 头像 CDN 外零网络请求**，出口由 `@connect credit.linux.do` 白名单强制
- **资金安全**：单号幂等（先落库再打款、重试复用单号、状态未知必须查单对账）、防重复发放
- **全程可审计**：名单快照、逐笔单号/交易号、事件流水、操作日志，支持导出 CSV / JSON

## 安装

Tampermonkey → 新建脚本 → 粘贴 `ldc-batch-distribute.user.js` 全文保存 → 打开任意 linux.do 页面 → Tampermonkey 菜单 → 「🧧 批量分发」。

## 使用流程

1. **密钥**：在 credit.linux.do 用户中心创建商户 API 密钥
2. **名单与额度**：粘贴用户 JSON（必需 `id`、`username` 字段；支持数组 / `{users:[…]}` / 整份 /u/用户名.json / 单个用户对象）→ 解析导入；或在输入框按用户名查询添加（同源接口自动补 id）；Alt+F 一键拉取我的粉丝；列表展示头像与信任级别（TL0-TL4） → 「统一额度」批量填充，或在每行输入框为**单个用户设置不同额度**；可勾选/取消、搜索过滤
3. **发放**：核对人数与总额 → 确认。可选「演练模式」**零网络请求**预演全流程；实发可暂停/停止/继续
4. **审计**：逐笔结果与事件流水；失败可重试（复用原单号）；「待对账」逐笔或批量查单定性；导出 CSV / JSON；存在待对账记录时禁止开新批次

## 安全模型

| 项目 | 做法 |
|---|---|
| 密钥存储 | 默认**仅内存**（刷新即失）；可选「加密记住」：口令 PBKDF2-SHA256（310k）派生 AES-256-GCM 密钥加密后落盘；保存会话后 secret 输入框自动清空，审计/导出永不包含密钥 |
| 密钥传输 | 仅随请求发往 credit.linux.do，由 `@connect credit.linux.do` 白名单强制 |
| 网络出口 | 除 credit.linux.do 支付/查单接口、linux.do 同源名单接口与 linux.do/ldstatic 头像 CDN 外零网络请求；无统计、无字体/样式外链；头像来自 avatar_template（加载失败自动回退本机色块） |
| 重复打款防护 | 幂等单号先于请求落盘、重试复用；网络异常/非 JSON 响应记「待对账」绝不自动重发，必须查单定性（已落地补记成功、未落地转失败）；待对账未清零禁止开新批次 |
| 金额 | 以「分」整数计算（避免浮点误差），最多两位小数，单笔上限 100 万 LDC |

## 本地开发与测试

```bash
npm install
npm test          # 用户脚本 e2e 测试（全部 mock，无真实网络）
```

- `test/e2e.test.mjs` — jsdom 端到端（GM stub + mock credit 接口），8 项
- `test/harness.html` — 浏览器手工调试 harness（GM stub + mock 接口，静态服务 `test/` 后打开）

覆盖：名单解析/去重/跳过、统一与单独额度、密钥校验（好/坏）、secret 不落盘、演练零网络、mock 实发（成功/余额不足/收款人不存在/断网未知）、查单找回、重试复用单号、加密记住与解锁/错误口令拒绝、中断恢复、审计导出删除、待对账拦截。

## 注意事项

- 请勿在多个标签页同时发放；打款即时到账、不可撤销，发放前务必核对总额
- 实发前建议先给自己转 0.01 LDC 验证链路；「演练模式」不产生任何请求与扣款
- 审计批次本机最多留存 50 个（超出自动清理最旧），需要长期留存请导出 JSON
